# RC-2026-001 — Login móvil sin scroll

Alcance: `/login` de `apps/app-conductor` (Next.js y su WebView). El proyecto independiente `app-conductor-native` no forma parte de este cambio.

La pantalla usa `100dvh` como base y sigue la altura y el desplazamiento de `visualViewport` cuando el teclado cambia solamente el área visible. Los campos, el botón y los enlaces se compactan por altura disponible mediante container queries. El bloqueo de scroll existe únicamente mientras se monta el login, incluso durante su carga.

Se conserva el envío de credenciales, el destino seguro `next`, el recorrido de primer arranque y las rutas existentes de recuperación, registro y documentos legales. El banner global de sincronización se omite en `/login`.

## Regresión automatizada

Archivo: `tests/e2e/login-mobile-rc-2026-001.spec.ts`.

Resultado del 17 de octubre de 2026, con Node 24: build del paquete, typecheck y ESLint aprobados; **12/12 pruebas E2E aprobadas** en Chromium, WebKit y Mobile Chrome sobre el build de producción (33.6 s). Se revisaron visualmente capturas de 320×568 y 320×284. El build conserva advertencias en archivos ajenos al ticket.

- Tamaños 320×568, 360×640, 390×844, 430×932 y paisaje 667×375.
- Área disponible 320×284 para simular el teclado con resize del documento.
- `visualViewport` de 320 px y offset de 24 px para simular resize y desplazamiento independientes del documento, conservando el foco.
- Formulario y CTA dentro de la pantalla, sin solapamiento con el soporte.
- Soporte dividido por igual, con objetivos táctiles de al menos 44 px.
- Error de autenticación simulado, envío con Enter y navegación de recuperación/registro con retorno al login.

Con el servidor local en puerto 3001 y configuración de prueba (sin credenciales reales):

```powershell
$env:PLAYWRIGHT_SKIP_WEBSERVER = '1'
$env:PLAYWRIGHT_SKIP_GLOBAL_SETUP = '1'
$env:PLAYWRIGHT_DISABLE_AUTH_ARTIFACTS = '1'
pnpm exec playwright test tests/e2e/login-mobile-rc-2026-001.spec.ts --project=chromium --project=webkit --project='Mobile Chrome' --no-deps --workers=1
```

Ejecutar desde `apps/app-conductor`. Las pruebas usan una sesión vacía y marcan el onboarding como visto. La autenticación de error se intercepta; no validan credenciales contra el servicio real.

Únicamente el caso de errores de autenticación usa `bypassCSP` para permitir el host ficticio del fixture. Los casos de layout y navegación conservan la CSP de la página; esta suite no sustituye las comprobaciones de seguridad.
