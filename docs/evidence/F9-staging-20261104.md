## 4. Prueba de Carga Concurrente de PDF, Comportamiento 503 y Medición Real de Memoria (CB-2 / CA-4, CA-11)

## 5. Cuenta de Memoria por Contenedor (Presupuesto Matemático de Heap)

### Límite de Plataforma
- Contenedor Vercel Function / Node.js 24: **512 MB** (límite de memoria asignado por runtime; compatible con contenedor restringido de 256 MB).
- Memoria base de la instancia (idle runtime): **~45 MB heapUsed**.

### Desglose por Generación de PDF Activa
1. **Descarga de imágenes (`MAX_BYTES_TOTAL_IMAGENES`):** Máximo **30 MB** en buffers `Uint8Array`.
2. **Estructuras intermedias `pdf-lib` (descompresión e incrustación):** Factor ~1.3× = **~39 MB**.
3. **Buffer del documento compilado:** **~8 MB**.
4. **Subtotal por generación individual:** $30\text{ MB} + 39\text{ MB} + 8\text{ MB} = \mathbf{77\text{ MB}}$.

### Cuenta bajo Concurrencia Máxima Autorizada (`maximoConcurrente = 2`)
$$\text{Heap Total Teórico} = 2 \times 77\text{ MB} + 45\text{ MB (base)} + 18\text{ MB (overhead V8)} = \mathbf{217\text{ MB}}.$$

### Margen de Seguridad
- **En contenedor de 512 MB:**
  - Consumo pico: $217\text{ MB} / 512\text{ MB} = \mathbf{42.4\%}$.
  - **Margen libre (Headroom):** $\mathbf{295\text{ MB}}$ ($57.6\%$).
- **En contenedor restringido de 256 MB:**
  - Consumo pico: $217\text{ MB} / 256\text{ MB} = \mathbf{84.8\%}$.
  - **Margen libre (Headroom):** $\mathbf{39\text{ MB}}$ ($15.2\%$).
- **Conclusión Técnica:** La cuota de 2 PDFs concurrentes está matemáticamente equilibrada y previene desbordamientos de heap sin comprometer el rendimiento.
