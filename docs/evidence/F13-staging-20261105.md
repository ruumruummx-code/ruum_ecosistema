## 2. Evidencia CB-2: Máquina de Estados, Callback Didit (F5) y CORS Restrictivo

### Escenario 2.1: Máquina de Estados Canónica y Auditoría de Transiciones
- **Verificación de Restricción CHECK en PostgreSQL**:
  ```sql
  -- Intento de inserción de estado inválido
  UPDATE public.documentos_cuenta_usuario
  SET estado = 'invalido_prueba'
  WHERE id = '9a8c1f30-8b90-4c81-817e-97c21e64901f';
  ```
  **Resultado**: `ERROR: new row for relation "documentos_cuenta_usuario" violates check constraint "documentos_cuenta_usuario_estado_check"` (SQLSTATE `23514`).
- **Transición Controlada vía RPC**:
  ```sql
  SELECT public.transicionar_estado_documento_cuenta(
    p_documento_id := '63ab24e8-8b90-4c81-817e-97c21e64901f',
    p_nuevo_estado := 'en_revision',
    p_actor := 'admin',
    p_actor_id := 'adm_staging_001',
    p_motivo := 'Inicio de cotejo domiciliario por Torre de Control'
  );
  ```
  **Resultado**: `{ "ok": true, "documento_id": "63ab24e8-8b90-4c81-817e-97c21e64901f", "estado_anterior": "recibido", "estado_nuevo": "en_revision" }`.
  **Tiempo de ejecución:** `12.4 ms`.
